# Milvus 原生 BM25 词法召回与对照

状态：`reference`
日期：2026-10-09

对应 BR-04、BR-06、BR-08 和 `feat/lexical-bm25`。Milvus 优先方向的首批实现是词法索引；dense 仍使用 Qdrant，完整 dense 迁移、影子查询与生产切读没有完成。

## 实现与可见性

Java 后端通过 Milvus 2.6 REST v2 使用原生 BM25。collection 保存 owner/source/version/检索块 ID 和原始 ASR/OCR 文本，使用 `jieba` tokenizer + `lowercase` filter，BM25 sparse inverted index，k1=1.2、b=0.75。collection 已存在时校验字段、analyzer、BM25 function 和索引 metric；不会删除或覆盖不兼容 collection。方案依据 [Milvus 全文检索](https://milvus.io/docs/full-text-search.md) 和 [2.6 中文分词说明](https://milvus.io/docs/v2.6.x/chinese-analyzer.md)，具体中英混合行为由实机测试验证。

启用后，新 generation 在 Qdrant dense 写入之后执行 Milvus 词法写入，全部成功才发布 MySQL 当前版本。写入或计数对账失败时旧 READY 仍可查。默认 `MILVUS_BM25_ENABLED=false` 保留现行运行配置；显式启用后 `keyword` 使用 BM25，`hybrid` 并行 dense/BM25 后做 RRF。`vector` 单独查询 dense；HTTP `like` 为固定旧词法对照入口，不进入 Milvus。

V12 保存按 backend URL/collection/analyzer profile 隔离的 generation 完成回执。查询先检查范围内所有已发布版本都有回执，再用同一 owner/source/version 过滤和 Strong consistency 核对实际文档总数。未完成回灌、丢失文档或 Milvus 请求失败时，整个词法通道降级为兼容关键词，不把部分索引当完整语料。BM25 正常返回零命中不会触发降级。

目录范围由 MySQL placements 解析；Milvus 使用精确 source/version 对过滤，不能把两个独立 ID 列表交叉组合。命中后按 ID 回填 MySQL 检索块和原文，复核 source/version，并重新检查当前 owner/READY/目录授权。查询期间发布新版本沿用既有快照契约，撤权与目录移除则立即排除。保留的旧 Milvus 版本不是当前检索范围，历史物理清理仍待后续策略。

`POST /knowledge/sources/{sourceId}/lexical-index` 仅回灌当前 READY 的词法索引，验证 owner，复用 `knowledge:index:{mediaId}` 锁；不会改变原文版本或重新 embedding。`/knowledge/search/details`、ask/stream 的 warnings 携带降级原因，Vue/MCP 已接入。旧 `/knowledge/search` 保留数组，调用方需要诊断时使用 details。

## 固定真实开发集

[对照报告](../../eval/reports/milvus-bm25-dev-20261009.json)：同一 13 课程、674 原始时间窗、592 个当前检索块、BGE-M3/1024 维、原有 Golden 和授权范围，开发集 14 题（13 可回答、1 域外），K=8。保留集没有用于本次调参。每条请求保存命中、原文版本与降级警告，本轮无降级；未调用回答生成模型。

| 策略 | 必要原文片段 Recall@8 | 全部必要片段覆盖率 | 关键题全部片段覆盖率 |
| --- | --- | --- | --- |
| Qdrant dense | 94.7% | 92.3% | 100% |
| 旧 LIKE | 15.8% | 15.4% | 0% |
| Milvus BM25 | 84.2% | 76.9% | 0% |
| dense + BM25 RRF | 89.5% | 84.6% | 0% |

词法召回明显改善，但 RRF 没有超过 dense。`cross-cache` 在 BM25/RRF 下缺少一个必要原文窗口，`rag` 也不完整；域外题在 dense/BM25/RRF 下都有候选，不能宣称拒答完成。该结果证明词法通道实现与增益，不关闭 BR-04，也不自动切换默认配置。下一阶段处理重排/复合问题覆盖和拒答；不强行塞入不相关视频。

本轮小样本顺序请求的阶段延迟在 JSON 中保留；不作为生产 P95、容量或数据库 dense 性能对照。没有模型账单与 HA/资源压力实验，不能由 BM25 增益推导 Milvus ANN 优于 Qdrant。

## 实机与页面证据

- [基础设施验收](../../eval/reports/milvus-bm25-smoke-20261009.json)：16 项，真实 Milvus 2.6.24/MySQL/Qdrant/HTTP、592 块回灌、原文对账、目录移除/跨账号拒绝、缺回执降级、停机与重启恢复；原文版本和向量缓存数量不变。
- [Vue 验收](../../eval/reports/milvus-bm25-ui-20261009.json)：4 项，实际默认 hybrid 请求、原文展开、真实缺回执警告和恢复；[正常截图](../../eval/reports/milvus-bm25-ui-20261009.png)、[降级截图](../../eval/reports/milvus-bm25-ui-degraded-20261009.png)。使用临时验收主体，不是学生用户研究。
- [MCP 验收](../../eval/reports/milvus-bm25-mcp-20261009.json)：4 项，同一配置上游主体与 Web 的 BM25 命中一致、降级警告透传和恢复；不是多主体 MCP 验收。
- 后端 214 项（含 opt-in 实机 Milvus）、MCP 17、前端 26、离线指标 7 项通过，前端生产构建通过。CI 没有 Milvus 服务时跳过 1 个 native integration test，其余正常运行。

实机单测覆盖中文问句、HashMap/GC Roots、其他主体/目录/旧版本排除、幂等 upsert。真实课程 ASR 拼写会影响词法查询，单测中的规范英文文本不能替代真实课程指标。

## 复现与回退

1. 按 [证据基准说明](真实证据基准-2026-10-08.md) 准备独立 `/tmp` MySQL/Qdrant 快照与私有 benchmark session；不得对产品数据库运行验收故障脚本。
2. `docker compose -p video-kb-milvus-experiment -f docker-compose.milvus.yml up -d`，使用本机 19531/19093 和独立 named volume；本次容器在 `desktop-linux` context，需在命令中指定相同 context。
3. `bash scripts/milvus-benchmark-runtime.sh` 启动 19092，显式启用 BM25；执行 `python3 eval/milvus_bm25_smoke.py` 回灌并检查。该脚本绑定上述本机快照和 Docker context，包含停止/恢复独立 Milvus 服务的操作。
4. 设置私有 `KB_EVAL_TOKEN` 或账号环境变量，运行 `python3 eval/evidence_benchmark.py --base-url http://127.0.0.1:19092 --corpus-map eval/reports/evidence-block-map-20261008.json --strategies vector like keyword hybrid --split dev --search-details --require-no-warnings --lexical-profile videokb-bm25-jieba-lowercase-v1 --output <新报告路径>`。
5. 前端以 `VITE_DEV_PROXY_TARGET=http://127.0.0.1:19092` 在 15174 启动；可选安装 Playwright 并使用本机 Chrome，运行 `node eval/milvus_bm25_ui.mjs`。脚本只更改快照中的一条完成回执并恢复，保留所有原文/索引。
6. 设置 `MILVUS_TEST_URL=http://127.0.0.1:19531` 后执行后端 Maven 测试可运行 native integration；未设置则跳过。

应用回退关闭 `MILVUS_BM25_ENABLED` 后重启，继续 Qdrant dense + 兼容关键词，保留 V12、Milvus 数据和原 Qdrant 数据。切换 collection/URL 必须重新回灌，不能继承旧 backend 完成回执。生产发布和完整 dense 迁移仍遵循[向量数据库迁移决策与过程记录](向量数据库迁移决策与过程记录.md)。
