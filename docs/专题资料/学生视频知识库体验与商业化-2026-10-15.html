PRODUCT REVIEW · STUDENT FIRST · 2026-10-15

把学过的视频，变成遇到问题时用得上的资料

首批试用者：学生。先验证“找回讲解 → 跨课对照 → 留下复习成果 → 再次使用”，再决定付费权益。网页和学生自己的 Agent 都是使用入口。

产品草案 / 演示原型　课程、时间片段、回答与运行状态全部为虚构示例；按钮只切换演示，不会上传、检索真实内容、连接 MCP 或扣费。商业参数全部是假设，尚无学生付费/留存数据。

目标设计，非已实现清单
01 · 课程来源

课程 / 课时 / 版本

知道来自哪里，谁可查看，材料是否已更新。保留原视频，不把摘要替代原件。

02 · 原始证据

转写 / 屏幕文字 / 时间

引用能回原片；告诉学生哪里没有解析完整。OCR不能直接等同于理解操作过程。

03 · 可维护条目

定义 / 条件 / 步骤 / 反例

每项归纳带证据，AI草稿与学生笔记、教师确认分开标识。

04 · 跨课对照

同一问题的不同讲法

比较前提、版本和冲突；不要把不同课程的结论拼成一个无条件答案。

05 · 复习成果

复习卡 / 对照表 / 清单

学生可编辑导出，保留引用。课程变化后提示过时，不让学习成果悄悄失去依据。

06 · 持续使用

网页 / Agent / 再次复习

Agent取原文，学生核对并使用。靠下一次任务的价值验证留存，不只靠提醒。

首批适合讲授与课件型课程。 编程录屏需要保留原片核对；无语音操作、实验动作或强视觉内容需要额外理解能力与专项验收。不能把所有视频都当成“转文字就解决”。

从学生价值走到真实付费

先证实反复复习需求，再测课程包与学习周期权益。每一步都要记录流失原因。

受限体验

先证明能解决问题

授权示例与少量自有课程体验；给出费用/额度边界，不先承诺无限处理。

课程 / 学习周期包

优先验证的收费形式

固定新处理分钟、存续时间、问答预算与导出权益；贴近一门课或一次备考。

持续学习月卡

复用出现后再测

多个课程持续新增和复习的学生才可能需要。19/29/39元是报价实验候选，未定价。

谁付款？ 首批假设是学生本人。Agent是调用端，Milvus和MCP是实现与入口。班级、教师或主理人合作需要后续证据与权限交付，当前不能直接售卖团队版。

机会存在，也有现成替代

官方产品供给事实，不等于学生需求、增长率或本项目优势。核验日期：2026-10-15。

Google Notebook 类产品：来源问答已有成熟替代

官方帮助支持将公共、有字幕的YouTube视频文字转写作为来源。

查看官方来源

推论：泛化“视频转写+聊天”难以单独构成购买理由，要在具体学生任务上实测。

Panopto：视频知识已经进入AI工作流

其官方页面已有视频知识问答、原片时刻引用和MCP接入。

查看官方MCP介绍

推论：支持MCP本身不是独占差异；我们需要证明学生的查课与复习流程更合适。

TwelveLabs：视频模态与持续成本要分开

官方检索覆盖语音、视觉与动作，收费分索引、基础服务与调用。

官方收费结构 · 官方检索说明

推论：先聚焦讲授型课程，计清新处理、问答、存储和重试；不以低价无限视频承诺驱动亏损增长。

候选差异要靠任务证明： 中文技术课程复习、跨课前提对照、原片证据、可携带复习卡和自己的Agent。首批实际试用者的学科与需求确认后，再决定哪些值得投入。

这是可审阅的产品候选方案，不是上线公告。完整研究、旅程、功能边界、商业假设与验证门禁见 学生产品 PRD；工程可靠性另见 架构评审。
