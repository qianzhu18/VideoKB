# 通用效率型视频知识库：定位与产品方案

状态：`draft`
最后复核：2026-10-15

负责人本轮方向：将产品包装为“通用效率化的视频知识库”。本稿据此扩展定位；学生仍是负责人最容易接触的首批试用者，学生场景不再限定产品身份。此前 [学生方案](学生视频知识库需求-2026-10-15.md) 保留为细分场景参考；[交互原型](通用效率视频知识库体验-2026-10-15.html)可切换任务场景，所有内容均为虚构演示。

定位已获负责人明确；场景功能、权益、费用、指标和实施顺序仍是候选，不能据此认定开发完成或已验证市场需求。

## 1. 产品摘要

**产品类别：通用效率型视频知识库。**

**对外表达：把视频变成可查证、可整理、可复用的知识，让你和 Agent 随时用起来。**

用户带着当前任务导入获准使用的视频，在授权范围内找到原片讲解、对照多个来源，把结果保存为有出处的笔记、步骤或工作资料，并在网页和自己的 Agent 中继续使用。

“通用”指复用同一套资料管理、提取、检索、证据和 Agent 调用能力；体验按要完成的任务组织。任务模板和实际支持的视频类型分别验收，不承诺任意视频都已被完整理解。Milvus 是后续优先技术栈，MCP 是知识调用入口；二者的技术选择不直接构成用户购买理由。

## 2. 角色与边界

| 角色 | 使用目标 | 当前边界 |
| --- | --- | --- |
| 个人用户 | 少翻视频、快找讲解、积累自己的可用资料 | 第一版可复用现有用户所有权与私有知识空间 |
| 外部 Agent | 按任务发现范围、检索、补查、读取原文与引用 | 保留五个只读工具，实际客户端任务验收待补 |
| 学生首批试用者 | 找课程内容、跨课对照、复习资料复用 | 最容易接触的验证样本；不能将其结果自动外推到企业/创作者 |
| 团队/培训组织 | 成员协作、内部经验复用 | 候选扩展；成员空间授权、管理、审计与实际需求未交付 |
| 负责人 | 选择场景顺序、权益和商业实验 | 本轮确定通用定位，不自动批准所有场景功能、定价或团队上线 |

不推翻此前学生需求研究：观察真实学习任务可以验证“视频→证据→可复用产物”的基础流程。工作复盘、培训和内容研究需要各自真实用户与语料，不能只换文案就标记验证完成。

## 3. 背景与发展方向

现有产品已有媒体入库、空间/目录、跨视频检索、单轮引用问答、回看与 MCP；主要欠缺是任务入口、可维护知识资产、完整提取状态、失败恢复体验、真实 Agent 闭环和商业权益。

发展路线建议为：**个人视频资料管理 → 按任务查证与整理 → 网页/Agent反复使用 → 经需求与权限验证后扩展团队。**

已有官方市场事实及来源保留在 [学生方案的市场核查](学生视频知识库需求-2026-10-15.md#32-市场信号与推论分开)：Google 的视频转写来源问答、Panopto 的视频知识与 MCP、TwelveLabs 的多模态检索与分层收费。它们支持该方向已有产品供给，但不证明本项目已形成差异化或付费需求。候选差异应通过具体任务的耗时、证据、复用与成本对照验证。

## 4. 目标与衡量

核心结果：用户在真实任务中减少反复翻找和搬运，把正确证据转为下次仍可使用的资料。

建议分别记录：

1. 首次价值：导入后完成一次正确检索、原片核对和任务产物保存的比例与耗时。
2. 完整性与可信度：必要来源覆盖、错误引用、提取缺口是否可见、用户需要修正多少内容。
3. 复用：后续任务中再次引用同一来源或知识条目的情况，而非累计上传量。
4. Agent效果：真实工具调用任务完成率、补查与错误恢复、引用正确性；网页使用独立计量。
5. 商业：可交付权益的真实付费、续用/退出原因、每周期计算/存储/服务成本。

以上没有本轮实测数值。先与用户的原方法对照形成基线，再确定阈值；不承诺固定省时比例、学习效果或生产容量。

## 5. 场景入口：卖要完成的事

首页主动作建议为“导入视频”和“查找知识”，并提供以下任务入口。学习仍为首批验证场景；其余为目标体验演示。

| 任务入口 | 典型问题 | 输出候选 | 额外约束 |
| --- | --- | --- | --- |
| 学习与研究 | 几段课程对同一问题怎么解释，适用条件有何差异 | 对照笔记、复习卡、研究摘录 | 归纳与原文分开，课程版本和未覆盖点明确 |
| 工作复盘 | 这次分享/讨论提出哪些观点，哪些事项需要再确认 | 复盘摘要、待办草稿、争议清单 | 发言人、决定与建议不能混淆；责任人/日期需人工确认，当前未证明自动准确归属 |
| 操作与培训 | 某个功能怎样操作，前置条件与常见错误是什么 | SOP草稿、检查清单、故障排查步骤 | 原片核对；OCR不等于理解动作或流程，强视觉/高风险操作另验 |
| 内容研究 | 多个访谈/演讲有哪些共同观点与分歧，来源在哪 | 观点对照、素材索引、提纲草稿 | 保留来源与上下文，不把AI归纳当逐字引文，不默认公开私有原片 |

这些入口复用资料与证据服务，不立即建设四套独立产品或承诺全部自动化。只有经过明确用户任务验证的入口才可作为正式可售能力。

## 6. 价值主张：视频怎样变成可用知识

```mermaid
flowchart LR
  A[视频与补充资料] --> B[原文证据与提取缺口]
  B --> C[主题与知识条目草稿]
  C --> D[跨来源查证与比较]
  D --> E[笔记 / 清单 / SOP等任务产物]
  E --> F[网页与Agent持续复用]
  F --> G[来源变更 / 撤权 / 更新提示]
```

源资料、证据、归纳与产物应保持可追溯关系：

- 源资料：来源/授权范围、媒体、版本、目录引用。
- 原始证据：原文 ID、版本、真实时间窗、转写/OCR与提取完整度。
- 知识条目：主题、适用条件、要点/步骤、反例/缺口、证据列表、编辑与审核状态。
- 任务产物：用户选择的笔记/清单/提纲等草稿，保留引用、自己的编辑与来源状态。
- 复用：在网页或Agent当前任务中再次引用；来源更新/撤销后重新核权，不以旧回答当新事实。

已有原文、版本/时间、检索、引用与 MCP 构成基础；知识条目、任务模板保存、资产更新提醒并未因此成为已实现能力。学生的复习卡是通用知识资产的一种展示；工作待办和SOP也是需单独验证的展示。

## 7. 体验与商业闭环

### 7.1 主体验

**带着任务进入 → 看一个对应示例 → 导入自己的资料 → 预检支持范围/成本 → 抽检质量与缺口 → 查证并回原片 → 整理任务产物 → 网页/Agent继续使用 → 更新、扩容或导出退出。**

双入口同等保留：网页用于管理与直接使用，MCP用于外部Agent调用。同一授权范围与证据服务支撑两种入口；MCP只读，管理与重试由获授权用户执行。

候选导航：任务首页、我的视频、知识空间、我的成果、连接Agent、用量与设置。正常使用不要求用户理解向量数据库、端口或分析profile；运行诊断与高级设置单独呈现。

### 7.2 商业结构建议

| 层次 | 候选权益 | 进入条件 |
| --- | --- | --- |
| 体验 | 授权示例 + 成本可控的个人资料试用 | 先证明一次真实任务价值，费用边界透明 |
| 个人效率 | 周期内新处理分钟、资料保存、问答预算、知识成果导出与MCP调用 | 有自发复用和可承担成本；价格由真实报价/支付实验决定 |
| 重度使用 | 更大处理/存储/调用预算、批量整理、任务模板等已验证能力 | 额外权益确实被需要，实际成本可计量 |
| 团队协作 | 成员/空间授权、管理审计、协作与组织支持 | 多主体、数据边界、协作需求与交付先验收；当前不是可售团队版 |

底层计量包含新增视频分钟、存储周期、检索调用、服务端生成与失败重试；对用户呈现清楚的任务权益与预算。外部Agent只取证据时，答案生成可能由用户自带模型承担；Agent调用服务端ask仍有服务端生成成本。

“学生学习周期包”继续作为首批细分价格实验，不强行决定通用产品只卖课程包。付费依据是持续查证、整理和复用的结果；未验证前不确定价格、不承诺无限视频或固定省时收益。

### 7.3 验证与推广路径

先在负责人可接触的学生中验证主链路与付费假设，再有针对性找工作复盘/培训/内容研究的真实任务。每个新场景带着自己的材料、原方法与成功标准验证；不凭通用定位推导“所有人都需要”。

首轮触达用完整结果样例：一个问题、两处原片依据、一份可复用产物。留存看下次是否自发再用，扩容看新增预算是否必要，退出应允许按明示规则导出自己的成果。成员邀请与内容合作须有权限模型和真实请求，再作为增长方向。

## 8. 发布顺序与已有工程的关系

1. 同步通用定位与任务入口演示，学生方案作为首批场景参考；本轮已形成文档与原型。
2. 先在一个真实场景跑通资料导入、质量核对、跨视频查证、原片回看与产物保存；产物模型先做小范围，不一次自动生成所有模板。
3. 完成真实Agent只读闭环和失败恢复、证据完整性；对齐 [架构候选包A–E](智能体知识库产品化评审-2026-10-14.md#8-建议实施包与门禁)。
4. 用复用与成本记录验证个人权益，课程包/月度预算按真实选择调整。
5. 经新场景实测后再扩大任务模板；团队能力在多主体隔离和协作需求明确后建设。

Milvus优先方向、Qdrant保留与迁移门禁继续沿用；通用定位不表示完整dense迁移、多人共享、全模态视频理解、真实支付或各任务产物已经交付。当前实现事实见 [当前交付状态](../当前交付状态.md)，业务要求见 [agent.md](../../agent.md)，已批准队列仍见 [待办事项](../待办事项.md)。
