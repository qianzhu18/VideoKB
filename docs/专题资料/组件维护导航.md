每个会改代码的组件一页知识卡：接到该组件任务时先读本页，再按需进入源码。卡片结构固定为五节——职责与流程图、选型与约束（含被否方案）、修改历史、待办、文字版测试案例。

全局事实（业务验收、数据流总图、交付状态）不在本目录重复维护，分别以 [agent.md](../../agent.md)、[当前后端架构](../系统架构与技术流程.md)、[当前交付状态](../当前交付状态.md) 为唯一活动位置；本目录卡片是组件视角的入口，冲突时以全局活动文档为准。

## 维护规则

- 组件行为变更时核对对应卡片并更新受影响的流程分支、选型约束和测试案例，随后按 [文档协作规范](../文档协作规范.md) 更新全局文档；这是 Git 交付门槛的一部分，见 [agent.md 交付与文档更新要求](../../agent.md)。
- PR 合并时在对应卡片"修改历史"追加一行（日期 + 一句话 + PR 号）。
- 卡片内不复制精确测试数量与指标数字，链接 [当前交付状态](../当前交付状态.md) 与报告。
