# 真实课程证据基准

状态：`active`
最后复核：2026-10-08

对应 BR-04、BR-08 与 `test/evidence-benchmark`。题目由工程人员依据真实课程转写编写，是工程测试题，不是学生访谈或社区反馈。首期问题要求见 [agent.md](../../agent.md)。

## 冻结的数据与指标

[Golden v1](../../eval/evidence-golden-v1.json) 包含 23 题，开发集 14、保留集 9；20 题可回答，3 题域外。跨视频关键题必须找全全部必要片段。每个必要知识点可标注多个替代片段，知识点之间是 AND，替代片段之间是 OR。

[当前索引原文快照](../../evaluation/seeds/course-index-snapshot-v1.json) 固定 13 门技术课程、674 个 ASR/OCR 原始时间窗。原归档仍保留；两者有 23 个文字修订窗口，时间边界未变化，见 [修订清单](../../eval/reports/corpus-revision-20261008.json)。Golden 原文引用全部在当前快照中精确存在。派生摘要不能作为原始证据。

`requiredEvidenceRecall@8` 计算全部必要片段的找回比例；`allEvidenceRate@8` 计算题目是否找全；`criticalAllEvidenceRate@8` 单独检查关键跨视频题。命中一个来源不足以通过。空检索率不是问答拒答正确率。工程门槛暂定必要证据 Recall ≥ 0.8，关键题全覆盖；保留集用于最终验收，不用于改写问题或调阈值。

## 基线与限制

[开发集基线](../../eval/reports/evidence-baseline-dev-20261008.json) 使用当前 Qdrant dense、MySQL LIKE 和 RRF。必要片段 Recall 分别约为 89.5%、5.3%、68.4%；关键跨视频题均未找全。当前混合策略未满足业务验收。固定问题较长，LIKE 中文整串拆词不足；现有摘要重复也会聚集向量结果，需要分块与召回对照，不能据此断言更换向量库能解决。

[保留集基线](../../eval/reports/evidence-baseline-holdout-20261008.json) 是开发前记录。后续开发仅查看开发集；发布阶段再运行保留集。

模型为 BAAI/bge-m3；真实既有向量与五分钟摘要来自已有索引，查询向量调用真实配置服务。没有重跑 ASR/OCR，没有调用问答模型。独立 MySQL/Qdrant 快照仅修改测试主体的授权 payload，向量数值未改变。原数据库和向量目录未修改。成本未取得账单，标为 null；模型价格环境值为零不能证明免费。

策略顺序执行，共享查询缓存，延迟包含冷暖差异，单进程小语料结果不能代表生产容量或公平的延迟对照。发布基准需随机顺序、热身与混合负载。Git SHA、Golden SHA、映射、模型、索引版本及原始命中均写入报告。

## 复现与保护

1. 停止原服务后，将 MySQL/Qdrant 数据复制到 `/tmp/videoagent-benchmark-*`；运行独立容器，端口 13307/16333。不要挂载原目录。
2. `scripts/evidence-benchmark-runtime.sh` 使用 19092、独立 Redis DB/MQ topic，关闭知识任务自动投递；此开关仅停止 outbox 调度，不是通用只读数据库权限。
3. `eval/prepare_snapshot_benchmark.py` 验证快照挂载、674 个原文时间窗与冻结语料，再创建临时主体。凭据存入权限 0600 的临时文件，不进仓库。报告映射不含凭据。
4. 设置 `KB_EVAL_TOKEN`，运行 `python3 eval/evidence_benchmark.py --base-url http://127.0.0.1:19092 --corpus-map eval/reports/evidence-baseline-map-20261008.json --split dev --output <新报告路径>`。保留集需要显式 `--split holdout`。
5. `python3 -m unittest discover -s eval -p 'test_evidence_*.py'` 检查错误来源/时间/摘要、重复结果、组合问题和原文锚点。CI 仅运行离线指标测试，不调用付费模型。

导出工具拒绝覆盖不同内容的冻结语料。改题、语料或标注须增加版本；不得改写旧报告后声称同数据提升。
