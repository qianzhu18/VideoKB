# 文档协作规范

状态：`active`

## 一个事实只有一个活动位置

产品要求与验收在 [agent.md](../agent.md)；当前交付状态在 [当前交付状态](当前交付状态.md)；待推进工作在 [待办事项](待办事项.md)；现行结构在 [当前架构](系统架构与技术流程.md)；操作契约在 SOP；某次测试/评测结果在报告；AI 协作约束在 [AGENTS](../AGENTS.md)。总索引负责导航与概述，不能另造状态清单。

仓库外笔记只保留研究与设计背景，不能成为仓库内文档不可缺少的唯一依赖。候选设计与历史材料须链接当前说明。

## 代码变更怎样触发文档更新

| 变更 | 同步文档 |
| --- | --- |
| 新增或改变业务能力 | agent.md 对应 BR + CURRENT + MASTER_TODO + 验收证据 |
| 内容模型、任务、版本或检索边界变化 | 当前架构 + 相关迁移/兼容说明 |
| HTTP/MCP 参数、工具、认证变化 | MCP SOP / 体验 SOP + 兼容说明 |
| 页面操作变化 | 体验 SOP；保存对应页面验收证据 |
| 状态/完成范围变化 | CURRENT；完成项退出活跃队列并保留证据链接 |
| 评测数字变化 | 保存版本化报告与 manifest，再更新 CURRENT 的证据链接；不覆盖旧报告口径 |
| 组件行为变化（流程、接口、页面、工具） | 对应 [组件知识卡](专题资料/组件维护导航.md)：流程图、选型约束、测试案例随行为更新 |
| Git 分支推进 / commit / PR 合并 | 先核对 agent.md 的 Git 交付门槛：对应文档全部同步后才 commit/push/merge；PR 合并时在组件卡修改历史追加一行（日期 + 一句话 + PR 号） |

行为已经变更但文档仍指向旧流程时，不能称为交付完成。改完需检查链接、锚点与过时表述，并确认仓库内入口可独立阅读。

每个变更交付时按顺序留下这条链：**需求/问题 → 改动路径与取舍 → 代码/迁移 → 验证案例与报告 → 状态入口**。组件卡保留“为什么曾这样做”和可重复执行的案例；精确结果放报告，`CURRENT` 只链接已核实的结果。没有运行的文字案例标为待验收，不能写成通过。多组件变更逐一核对受影响的卡片；未影响的章节无需机械重写。PR 合并后的历史行记录真实提交/PR，不预填未发生的结果。

## 文档分类、生命周期与索引

`总索引.md` 是唯一入口，只维护入口和分组目录，不复制状态、队列或评测结论。根目录保留长期主文档；`专题资料/` 放组件知识卡、候选方案和专项工程记录；`历史归档/` 放已替代材料和旧证据；`图片附件/` 放被正文引用的媒体及样例。三个目录不再增加子目录。

文档生命周期按用途管理：候选稿标 `draft`，现行维护说明标 `active`，有历史价值但不再维护的材料标 `reference` 或 `archived`。归档时先检查是否有替代文档，补替代链接，再移动文件、更新所有入链和总索引；不要只改路径而留下旧导航、空壳索引或过期说明。一次性报告只有在仍支撑活跃决策时留在专题资料，否则归档。任何归档都保留原始日期与结论语境。

专题资料按主题分组写在总索引中，不另建多份导航。唯一例外是[组件维护导航](专题资料/组件维护导航.md)，它是代码路径到组件知识卡的稳定映射，被协作规则和 agent.md 引用。

每次新增、移动、重命名、拆分或合并文档，必须同一轮完成：更新总索引；全仓库搜索旧路径并修复引用；检查文内相对链接与锚点；检查文档状态、事实归属和替代关系。只更新索引不算完成。

## 状态与命名

活动文档的状态值为 `active`，并写最后复核日期；候选方案 `draft`，背景或历史样例 `reference`，保留的旧版本 `archived`。`implemented-local` 属于交付范围描述，放在报告正文，不替代文档状态。

`docs/` 内所有文件使用中文主题名，包括索引、图片与 HTML；不保留英文旧入口。一次性报告按 `中文主题-YYYY-MM-DD.md` 命名，持续文档用中文主题名。

根目录只放总索引、当前状态、待办、系统架构、测试集评测、操作指南和协作规则。只保留三个一级目录：`专题资料/`（组件维护、候选设计和专项记录）、`历史归档/`（历史证据与旧稿）、`图片附件/`（截图、图表和事件样例）。不再按角色或每次任务创建子文件夹。

优先补充现有主文档；新建文件前确认现有文件无法承载。新增或移动文件必须同步总索引的完整清单与全仓库链接。历史记录不删除，保留原日期和适用范围；旧导航不留在专题目录冒充活动入口，归档后提供明确的替代链接。代码目录的 AGENTS.md、README.md、机器可读评测 JSON 和源码文件不属于 docs 中文改名范围。

## 证据口径

- 严格区分源码存在、单测、合成 AI/真实基建集成、真实视频、真实模型质量、生产运行与用户研究。
- 每次质量评测保存语料/query/模型/媒体或索引版本、时间、指标定义和 manifest；不同 Golden 不能作同数据 A/B。
- 来源命中不等于全部视频覆盖；逐字引用匹配不等于 claim 正确；health 不等于完整链路健康。
- 合成学生问题必须标为假设或测试资料，不能转述为真实学生反馈。未验证的社区规模、性能和发布日期不能写成承诺。
- 保留用户已有工作区修改；文档整理不替代生产部署、提交或发布授权。

## 链接检查

本仓库使用 Markdown 相对链接。维护时执行 `node scripts/check-doc-links.mjs docs`；归档或涉及 reference 时再加 `--include-archive --include-reference`。该仓库脚本是链接检查入口；若文档提及其他环境脚本，以本仓库现有脚本为准。
