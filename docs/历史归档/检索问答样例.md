**answer**:

根据视频内容，在做外卖或点评项目时，Redis缓存的常见使用套路包括以下几个来自不同项目的实例：

**来自《苍穹外卖》项目的应用：**
1.  **高频查询缓存**：将极少变化但高频查询的数据（如店铺营业状态）存入Redis，以减轻数据库压力。
2.  **数据缓存（如菜品）**：实现经典的缓存查询逻辑，先查Redis，未命中再查数据库并回填Redis。

4.  **读写锁保证一致性**：使用Redis锁（共享锁、排他锁）来保证数据库与缓存数据（如营业状态）的强一致性。

## [单视频·精确术语] MySQL 的索引为什么用 B+ 树而不是 B 树？

**answerability**: `SUPPORTED`

**answer**:

MySQL的InnoDB引擎选择B+树而不是B树，主要有以下两个关键原因：

1.  **减少磁盘IO，查询性能更好**：B树的每个节点（包括根节点和中间节点）都存储数据，导致一个节点占用的空间更大。节点空间大意味着能存放的指针数量减少，这会导致树的高度变高，从而需要更多的磁盘IO次数来查找数据。
2.  **范围查询（如 `BETWEEN`）性能优越**：B树在进行范围查询时，需要进行中序遍历，并在父子节点之间来回跳转，性能较差。而B+树的结构使得这种查询更加高效。

这些优势基于B+树的一个核心设计：非叶子节点只存储索引，不存储具体的数据行。
