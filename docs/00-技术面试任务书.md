# dovideo：技术面试任务书

## 一、项目为什么存在

本项目服务于 AI 应用工程 / 后端工程实习面试。目标是通过一个可运行、可测试、可演示的长视频理解 Agent，打通 Python 后端、RAG、受控 Agent 工作流和 Next.js 工作台的关键能力。

它不是为了先上线或包装成企业 SaaS。每个简历要点必须能在代码、测试、运行结果或演示录屏中验证；未完成的部分只能作为“下一阶段设计”说明。

## 二、当前已实现并必须吃透的主链路

```text
视频输入
  -> ASR 语音转写 与关键帧 OCR 并行
  -> 按时间轴合并为 VideoContext
  -> 5 分钟 Chunk / 摘要 / 关键词 / Embedding
  -> 混合检索相关证据
  -> Planner -> Executor -> Critic 受控循环
  -> Claim 级证据核验与结构化结果
  -> Checkpoint、预算、降级、SSE 事件与可观测
```

要能脱稿回答的不是“用了什么框架”，而是：

- 为什么不能把整条转写直接交给模型？
- ASR、OCR、向量库或模型挂了分别怎样降级？
- 同一视频换目标为什么不重跑 ASR/OCR？
- Agent 生成的结论如何绑定并核验时间戳证据？
- 重试、幂等、Checkpoint、预算终止各自解决哪一类问题？

## 三、唯一优先的产品增量：Collection

### 目标

把“单视频内检索”升级为“同一个学习资料分区内的多视频检索”，例如 `Python 学习`、`Java 学习`。它是面试项目的最小产品化增量，不是新开一个 SaaS。

### 最小范围

```text
Collection
  └─ Media（多个本地上传视频）
       └─ VideoContext -> Chunk -> Evidence

提问 -> 服务端固定 collection_id 过滤 -> 混合召回
     -> 生成带 videoTitle / timestamp / evidence 的回答
```

- 新增视频只解析、切片和写入该视频的 Chunk；旧视频不重复处理。
- 用内容指纹与版本字段保障重复提交和重新索引的边界。
- 结果必须能跳回本地视频对应时间戳；证据不足时应拒答或标注不确定。
- 首版只支持本地上传视频。网页、PDF、Markdown 和用户授权链接是后续 Source Adapter，不进入当前交付承诺。

### 不要做的事

- 不把“视频链接下载/抓取”作为面试亮点；不处理 DRM、付费墙、Cookie 汇集或绕过平台限制。
- 不为 Collection 强行引入多租户、支付、SSO、微服务、Kubernetes 或新的消息队列。
- 不把多个 Prompt 角色称为“多智能体平台”。项目当前正确表述是 **受控、证据约束的 Agent Workflow**。

## 四、面试技术栈与能力映射

| 能力 | 项目锚点 |
|---|---|
| Python 后端 | FastAPI、asyncio、Pydantic schema、REST、SSE、pytest |
| 长任务可靠性 | 阶段状态、幂等、重试语义、Checkpoint、死信/重放、预算熔断 |
| 多模态处理 | FFmpeg、60 秒 ASR、场景选帧、dHash、OCR、时序融合 |
| RAG | Chunk、Embedding、Qdrant、本地降级、关键词/向量/视觉混合排序、上下文预算 |
| Agent 工程 | Planner/Executor/Critic、结构化输出、证据校验、提示注入隔离、有限循环 |
| 工程质量 | 离线 FakeLLM、故障注入、金标评测、LangFuse 钩子、Docker Compose |
| 前端协作 | Next.js/TypeScript 工作台只展示任务状态、证据与提问闭环 |

## 五、学习与交付顺序

1. **先吃透现有核心**：按 `project-playbook.md` 和六支柱问答，逐条对应代码与测试。
2. **补 Collection 最小闭环**：数据模型、Collection 内检索、视频来源回跳、最小工作台。
3. **补证明材料**：真实样例、故障用例、评测集、测试、架构图和 2–3 分钟演示录屏。
4. **再写技术简历**：只写已经实现、可演示、可深讲的内容；Collection 未完成前不能写成跨视频知识库。

## 六、面试时的真实性口径

- 可以说：项目借鉴 DOVideo-AI 的工程思想，使用 Python 全新实现并增加 MCP、LangFuse、离线测试和评测框架。
- 可以说：大量编码由 AI Coding 辅助完成；本人负责边界定义、选型、审查、故障设计和测试行为契约。
- 不能说：有生产用户、线上 SLA、公开商业化、真实质量提升比例或已经完成的多源企业知识库，除非之后有可验证事实。
- 不能说：当前 OCR 是完整视觉理解；它只可靠提取语音、字幕及关键帧文字。
