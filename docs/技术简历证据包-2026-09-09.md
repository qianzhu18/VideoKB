## 1. 这不是“视频总结项目”，而是一段可验证的 Agent 工程经历

`dovideo` 最适合服务三个方向的技术简历：

| 目标岗位 | 项目证明的能力 | 最该强调的部分 |
| --- | --- | --- |
| AI 应用工程师 / Agent Engineer | 如何约束模型输出、管理上下文、评测与开放工具能力 | 证据约束 AgentLoop、提示注入边界、MCP、离线 FakeLLM |
| Python 后端工程师 | 如何处理长任务、失败、幂等、状态与实时反馈 | FastAPI、asyncio、Checkpoint、重试语义、预算、SSE |
| RAG / 多模态工程师 | 如何把长视频转成可检索、可回溯的上下文 | ASR/OCR 时序融合、5 分钟分块、混合检索、四级降级 |

面试官不需要相信“模型说它总结得很好”。这个项目能展示的是：**把概率性的模型调用收进可恢复、可预算、可验证、可测试的任务系统。** 这是它和普通调用 API 的视频摘要 Demo 的区别。

## 2. 当前可写入简历的事实

下列每一条都有实现或测试支撑。不要在简历中捏造用户数、线上吞吐、模型准确率、节省成本百分比或生产 SLA。

### 推荐版本 A：AI 应用工程师

**dovideo｜证据约束的长视频理解 Agent｜Python、FastAPI、asyncio、SQLite、Qdrant、FFmpeg、MCP**

- 设计 Planner–Executor–Critic 受控 Agent 工作流，以代码核验时间戳、来源文本与 claim 绑定，拦截模型的伪造证据；Critic 失败后按缺失时间段定向补检索，最多两轮修订。
- 构建 ASR 与关键帧 OCR 并行的 VideoContext：60 秒切片、场景检测、dHash 去重和时间窗融合，让结论可回跳至原视频证据。
- 实现长任务可靠性机制：内容/目标两级 checkpoint、幂等认领、可重试/永久失败分类、失败台账与重放、轮次/时长/Token 预算熔断；终态 checkpoint 命中时不再调用模型。
- 实现 5 分钟分块和关键词/语义/视觉混合检索，并为摘要、检索意图、embedding、Qdrant 分别提供降级路径；使用 24k 字符上下文预算控制输入规模。
- 将视频分析、证据检索和继续追问封装为 MCP 工具；以依赖注入与 FakeLLM 支持全链路离线测试，当前 60 项 pytest 通过。

### 推荐版本 B：Python 后端工程师

**dovideo｜可恢复的多模态视频分析任务系统｜Python、FastAPI、asyncio、SQLite、SSE**

- 设计异步分析 API：重复提交返回进行中状态，结果可复用，阶段事件通过 SSE 推送；任务按内容与目标摘要做幂等认领。
- 以 SQLite 作为 checkpoint 与失败台账真源、Redis 作为可选热缓存，区分“缓存丢失只影响性能”和“状态丢失会导致重复计算”的数据边界。
- 将重试性编码为异常类型，结合 1/2/4 秒退避、最多 3 次任务投递与死信重放；预算耗尽进入 `BUDGET_EXHAUSTED` 终态而非继续重试。
- 把视频处理拆为 ASR 与 OCR 两个异步分支，允许单路失败并保留另一条有效证据；双路失败携带原因上抛，避免配置错误被误判为瞬时抖动。
- 编写 60 个离线测试覆盖重试、幂等、预算、checkpoint、自修复、SSE 与证据校验，离线执行耗时约 0.3 秒（2026-09-09 本机验证）。

> 用其中一个版本即可。面向 AI 应用岗优先 A；后端岗优先 B。不要把两版简单拼接成长项目段落。

## 4. 2 分钟现场演示：让简历从“会说”变成“能证明”

先在本机执行：

```bash
cd /Users/mac/qianzhu\ Vault/project/videoagent/dovideo
source .venv/bin/activate
python -m pytest -q
python -m dovideo.demo
```

演示话术按以下顺序即可：

1. **10 秒：问题。** “长视频的难点不是生成摘要，而是模型引用是否可回看、失败后是否要重算，以及 Token 是否会失控。”
2. **25 秒：证据闭环。** 展示 demo 第一轮被纯代码护栏拦截、第二轮带补充证据通过；说明 Critic 负责语义检查，程序负责不能信任模型的事实核验。
3. **25 秒：成本与恢复。** 展示第二次运行 `0` 次模型调用；说明 context、草稿和终态三个恢复粒度分别避免重跑什么。
4. **25 秒：可靠性。** 指向预算、异常类型、失败台账和 SSE；说明为什么预算耗尽不能按网络失败继续重试。
5. **20 秒：工程诚信。** 现场运行 60 项测试；主动说清真实模型、真实视频链路、Qdrant/Redis 与前端工作台尚未形成可写入简历的联调证据。

这段演示比录一个“视频上传后出现总结”的视频更有技术说服力，因为它能回答面试官真正会继续追问的失败路径。

## 6. 让项目成为更强履历的三个增量，不要盲目扩栈

按“可展示价值 / 工作量”排序：

1. **真实样例与金标集。** 准备 3 个有授权视频和 10–20 个目标问题，记录证据支撑率、关键词覆盖率与失败案例。这样才能把“有评测框架”升级为“有可复现质量结果”。
2. **真实视频端到端录像。** 跑一条 FFmpeg → ASR → OCR → 证据回跳 → SSE 的真实链路，保留 2–3 分钟录屏和运行环境说明。它证明多模态管线不只是 fixture。
3. **最小 Collection。** 做本地多视频分区、Collection 内检索、标题+时间戳+原文回跳。它能把单任务 Agent 提升成明确的学习资料工作流，但完成前不能写入简历。

不建议为了简历额外引入微服务、支付、SSO、Kubernetes 或“多 Agent 平台”。这些名词不会增强项目的可验证性，反而会让面试追问越过现有证据。

## 7. 求职材料中怎样放置这个项目

- **项目排序**：投 AI 应用/后端岗时放在第一个项目；WorkIsland 可作为第二个项目，用来证明桌面端、多 Agent 适配与本地优先产品判断。
- **一页简历篇幅**：项目标题 1 行、简介 1 行、4–5 条 bullet；不要粘贴技术栈清单或完整架构流程。
- **作品集链接**：放仓库/代码快照、README、2 分钟演示录像和本文证据包；README 首屏先写问题、架构图、如何一键复现测试、真实边界。
- **面试准备**：先背“为什么证据需要代码核验”“失败为何能从草稿恢复”“为何不用消息队列”“为何不是泛泛 multi-agent”四个问题，再背数字和实现细节。
