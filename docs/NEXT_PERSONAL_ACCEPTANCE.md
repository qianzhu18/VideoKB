# 下一轮个人验收计划

状态：`active`，最后复核：2026-09-21

本轮以 `evaluation/technical-learning-v1.json` 为唯一语料清单。媒体文件保留在本地，不上传到 Git 仓库。目标是验证 VideoKB 可以在一组真实、长时长技术视频上完成可重复的入库、恢复和金标评测，而不是提前宣称质量或性能结论。

## 验收顺序

| 顺序 | 项目 | 通过条件 | 留存证据 |
| --- | --- | --- | --- |
| 1 | 语料完整性 | `verify_corpus.py` 对 13 条视频全部通过，文件数、大小、SHA-256 和时长与 manifest 一致。 | 校验命令输出。 |
| 2 | 三条冒烟入库 | 顺序处理 `01`、`06`、`13`，每条均生成 context 与 chunks，单路失败时保留可用证据或明确失败原因。 | 入库日志和每条任务状态。 |
| 3 | 恢复与幂等 | 在三条冒烟样本上重复运行入库命令，已有 context/chunks 不重新触发 ASR/OCR；人为中断后能从 checkpoint 继续。 | 两次日志对比和 checkpoint 记录。 |
| 4 | 全量入库 | 13 条视频全部进入同一语料版本，失败项可单独重试且不会阻断其余项目。 | 汇总日志，包含每条媒体 ID、状态、耗时和 chunk 数。 |
| 5 | 金标评测 | `eval_corpus.py` 输出完整 JSON 报告。每条案例满足结构完整、证据支持率 ≥ 0.8、关键词覆盖率 ≥ 0.8；全组通过率 ≥ 0.8。 | `evaluation/reports/corpus-golden-*.json`。 |
| 6 | 人工证据抽查 | 从网络、数据库、并发、框架、AI 五类主题各抽 1 条结论，核对结论、原始证据和时间戳可以对应。 | 验收记录中的 5 条截图或时间戳链接。 |
| 7 | 检索边界 | 准备 10 个问题，其中至少 2 个无答案问题。记录检索结果、无证据行为和错误案例，不把空结果或低置信结果改写为确定答案。 | 问题表和原始输出。 |

## 本轮不作为通过条件的事项

- 跨视频生成式 RAG 的 Faithfulness、Citation Precision、Timestamp overlap、P95 和成本。
- 真实 MCP 客户端端到端调用。
- Milvus、BM25、重排模型或线上多租户能力。

这些能力仍是后续工作，不能用本轮金标通过替代。

## 验收结束后的更新规则

通过时，将每个命令、报告路径和失败项写回项目 changelog 与评测说明。未通过时，保留报告，记录失败类别和复现命令，再决定是否调整实现、提示词或数据标注。不得覆盖旧报告来掩盖回归。
