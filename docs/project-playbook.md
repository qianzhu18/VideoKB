## 〇、怎么背这个项目(先读这节)

原作者的方法本质是**钩子记忆法**,我按他的经验适配成三步:

**第一步:七个钩子。** 简历每行亮点就是一个钩子,面试官 90% 的问题都从钩子发出。你不需要背项目全貌,只需要让每个钩子挂四层:①背景矛盾(为什么要)②选型对比(为什么是它不是别的)③实现流程(具体怎么做,带数字)④兜底追问(挂了怎么办)。背层不背句。

**第二步:三类记忆锚点。**
- 数字锚点(最容易被追问,也最容易显专业):60s 切片 / 0.35 场景阈值 / 30s 保底抽帧 / 汉明距离≤5 / 5 分钟分块 / 24k 字符预算 / 两轮上限 / 120s 时长 / 50000 Token / 打分权重 0.6+0.25+0.15 与 0.55+0.25+0.20 / TOP_K=3 / 证据检索≤8 条 / 1s-2s-4s 退避 / 3 次投递 / sha256 + U+2419 分隔符 / uuid5 确定性 id。
- 取舍锚点(高级感来源):砍了 RocketMQ/Redisson/MinIO/分片续传(单人本地场景是负资产);留了全部可靠性语义(幂等/重试/死信/checkpoint/降级)。每个取舍都能答"什么条件下我会加回来"。
- 故障锚点(兜底题的钥匙):每个组件记住一句"它挂了会怎样"——向量库挂→本地余弦;embedding 挂→纯关键词;摘要挂→原文 500 字;单路 ASR 挂→保留 OCR;全挂→带 cause 抛出;LLM 谎报→纯代码核验拉回;预算耗尽→终态不重试。

**第三步:背诵顺序与自测。** 先背总览两分钟话术(下面第二节),再按六支柱顺序(=简历顺序)逐钩子过四层,最后自测:随机说一个故障场景,要求 10 秒内说出影响面+降级路径+恢复粒度。说不出来就是没背会。

## 一、简历怎么写(技术点+产出,埋钩子不写流程)

> 项目名建议:vidoAgent / dovideo —— 面向长视频的证据约束 Video Agent
> 技术栈:Python FastAPI asyncio 多角色受控编排 SQLite Redis Qdrant FFmpeg MCP Next.js(进行中)
> 注意:编排是手写状态图式闭环,没有用 LangGraph 框架——面试如实说"框架无关的状态图,节点即角色、条件边即重检",反而能讲清"为什么不需要框架"。

项目简介:面向长视频内容理解的证据约束 Video Agent。将开源项目 DOVideo-AI 的核心工程思想移植到 AI 原生栈,支持目标驱动分析、Claim 级证据核验、断点恢复与 MCP 能力开放,离线全链路可测。

- 设计 Planner-Executor-Critic 受控 Agent 工作流,纯代码级 Claim 证据核验拦截模型伪造,按 Critic 反馈定向补证据并增量修订计划,两轮内产出时间戳可回溯的结构化结论。
- asyncio 双分支并行执行 ASR 转写与关键帧 OCR,场景变化检测 + 感知哈希选帧,按 60 秒时间轴融合语音与画面文字构建多模态 VideoContext。
- 长视频按 5 分钟分层摘要,结合关键词与 Embedding 混合检索(语义 0.6/关键词 0.25/视觉 0.15)选段,24k 字符上下文预算,四级降级链保证检索故障不阻断分析。
- 设计阶段级 Checkpoint(SQLite 真源 + Redis 热缓存),Executor 草稿先落盘再校验,终态命中零模型调用,内容级复用使换目标不重烧 ASR/OCR。
- 实现轮次/时长/Token 三闸门预算(模型调用超时=剩余预算),以异常类型显式建模重试语义,失败台账脱敏入库并支持重放。
- 通过 MCP Server 将视频分析能力开放为标准工具,集成 LangFuse 全链路追踪与金标评测回归(结构完整率/证据支撑率/关键词覆盖率)。
- 全链路离线可测:外部依赖(模型/ASR/向量库)全部接口化注入,60 个测试覆盖含"模型谎报通过被纯代码核验拦截"在内的真实故障模式。

(写法原则同原作者:一行一亮点,只写"技术点+产出"埋钩子,不写流程;细节留到问答展开。)

## 二、项目话术与真实性准备

### 1 分钟版

"dovideo 是一个证据约束的视频理解 Agent。用户给视频和分析目标,系统先把视频转成带时间戳的语音加关键帧文字证据,再按目标混合检索相关片段,最后由 Planner、Executor、Critic 三个受控角色闭环分析——每条结论必须绑定能回看原视频的证据,证据由代码核验而不是信任模型。它是对一个开源 Java 项目的核心思想的 Python 重实现,我补了 MCP、可观测和评测三个工程化维度,并且整个链路不依赖 API Key 就能完整测试和演示。"

### 真实性三问

- "代码是你写的吗?" —— 大量编码由 AI Coding 辅助完成,我主动说。我的工作是设计判断(哪些机制留哪些砍)、护栏语义定义、代码审查和测试锁定;60 个测试就是行为契约,AI 改坏任何一处会红。
- "和 DOVideo-AI 什么关系?" —— 场景和工程思想借鉴这个开源项目,我精读过它约 40 个核心类;实现是全新的 Python 栈,且 MCP/LangFuse/评测/离线架构是它没有的。借鉴思路、重写实现、讲清增量。
- "有生产数据吗?" —— 没有。离线 60 测试 + 可当场演示,不编造流量和指标;评测框架已就绪、用例集未沉淀,这是我说出来的边界,不是藏起来的坑。

## 三、AI Coding 方法论(这次重写的真实过程)

1. **精读先于生成。** 先派探索代理精读原项目 40 个核心类,产出移植蓝图(每条机制的行为契约:三角色 prompt 规则、钳制顺序、打分权重、checkpoint 键、14 条隐藏设计)。没有蓝图直接让 AI 写,得到的是形似神不似的玩具。
2. **骨架先行、依赖后装。** 先定目录与接口(LLM 协议、分支构建器、向量库、预算时钟),让 AI 在框架内填实现;外部依赖全部可注入,是后面离线测试的前提。
3. **测试锁行为。** 每个护栏先写失败场景测试(谎报 passed、伪造证据、预算超限、抖动重试),实现必须让测试变绿;60 个测试 0.3 秒跑完,重构才敢放手做。
4. **AI 当高级搜索引擎和码手,不当项目经理。** 需求拆解、取舍决策、边界审计是我做的;AI 幻觉靠交叉验证(它发明过不存在的 API)和测试兜底。
5. **审计文档。** 写文档时逐条对照代码:降级路径不写成主路径、框架不写成已有数据、未联调的明说未联调。

## 四、六条亮点拆解(钩子 → 四层)

### 亮点 1:受控 Agent 工作流 + Claim 级证据核验

- 背景矛盾:一次 LLM 调用有幻觉、漏覆盖、结构随机三个不可控,失败只能整体重烧。
- 选型:三角色分工(Planner 管覆盖/Executor 管证据绑定/Critic 管缺口)+ 确定性程序管其余;为什么不信 LLM 自查——利益冲突,谎报 passed 必须由代码拉回(有测试)。
- 实现:计划 1–5 任务≤500 字(repair 一次);Executor 固定 schema + claim 逐字复制;核验三层(时间戳落区间+source 兼容+归一化子串;claim 相等;结论覆盖率);钳制链 normalize→结构→证据→一致性。
- 兜底:不通过→rewrite-only 或三路合并补证据(margin=max(60s,段长));两轮耗尽→WITH_WARNINGS 不丢产物;结构化解析失败→严格 JSON 重发一次。

### 亮点 2:双分支并行 VideoContext

- 背景矛盾:公式/代码/图表文字在画面不在语音;小时级视频逐帧抽帧是灾难。
- 选型:ASR(叙事+时间轴)+ OCR(画面文字);ffmpeg scene 滤镜而非逐帧;asyncio.gather 而非 MQ(只有两个固定分支,无削峰诉求)。
- 实现:60s 切片(-segment_time 60 -reset_timestamps 1);选帧表达式 `eq(n,0)+gt(scene,0.35)+gte(t-prev_selected_t,30)`;pts_time 提取,丢失 i×30s 兜底;dHash 9×8 汉明≤5 去重;tesseract chi_sim+eng;60s 窗口键 ts/window×window 合并。
- 兜底:切片/帧级失败计数容忍;单路失败保留另一路;双路皆败 PipelineError 必须带 cause(否则参数错误被当抖动反复重投);帧引用降级 `path#timestampMs=` 锚点。

### 亮点 3:分层摘要 + 混合检索 + 上下文预算

- 背景矛盾:几万字转写直接塞=超上下文+噪音+烧钱。
- 选型:5 分钟 chunk 做检索单元;混合而非纯向量(日期/术语精确匹配靠关键词);Qdrant+本地余弦双路。
- 实现:摘要≤200 字+关键词;意图规划(semanticQuery/keywords/visualKeywords);打分 0.6/0.25+0.15 → Top3 → 0.55/0.25/0.20;uuid5 确定性 point id;24k 预算贪心装包首条保留;≤5 分钟短视频直通。
- 兜底:四级降级(意图→切词;embedding→纯关键词;Qdrant→本地余弦;摘要→原文 500 字),每级独立计数;第一次检索不完整由 Critic 覆盖检查兜底。

### 亮点 4:阶段级 Checkpoint + 三级复用

- 背景矛盾:长任务任何一步失败都不能从头重来;同视频换目标不该重烧最贵的 ASR/OCR。
- 选型:SQLite 真源+Redis 可选热缓存(先库后缓存);内容级/目标级两层键;digest=sha256(goal 或 mode+␟+goal)。
- 实现:28 阶段状态机;草稿(Executor 后落盘)→ Critic 续跑;终态命中 0 次调用+脏数据自修复归零;两段式用户修订(按前缀删旧 checkpoint)。
- 兜底:缓存丢失只影响速度;幂等键失败路径必须释放,否则重试全被误判重复。

### 亮点 5:预算三闸门 + 幂等 + 失败台账

- 背景矛盾:LLM/ASR 是按 Token 计费、会抖动的外部调用;重复执行=烧钱,失败静默=事故。
- 选型:轮次/时长/Token/成本四闸门各管一类风险;异常类型(Retriable/Permanent)而非字符串区分重试性。
- 实现:模型调用超时=min(超时,剩余预算);阶段边界检查;claim_active 主键冲突实现 SETNX;1s/2s/4s 退避 3 次尝试 + runner 3 次投递;失败脱敏(bearer/api_key/sk-→****,截 1000 字)+ 重放接口。
- 兜底:预算耗尽→BUDGET_EXHAUSTED 终态不重试;3 次投递失败→死信台账;重放前重设幂等键。

### 亮点 6:MCP + LangFuse + 金标评测 + 离线架构

- 背景矛盾:Agent 能力被锁死在自家 Web UI 里;prompt 改动没有回归防线;外部依赖让链路不可测。
- 选型:MCP(跨宿主能力总线)优于逐客户端集成;评测三指标(结构完整/证据支撑率≥0.8/关键词覆盖≥0.8);FakeLLM + 接口注入。
- 实现:三个 MCP tool;遥测 30+ 计数器 + LangFuse 钩子(观测故障不阻断);FakeLLM 按任务标记路由、可注入故障。
- 兜底:MCP 包未安装给出可读错误;LangFuse 未配置零开销;评测 runner 已测、用例集未沉淀(诚实边界)。

## 五、新兴 Agent 关键词 × 项目锚点(面试加分话术)

- **Harness Engineering**(2026 共识:Prompt→Context→Harness):证据核验、预算闸门、checkpoint、降级链、SSE 就是"模型外的一切"——本项目是按 Harness 思路有意设计的,不是事后贴标签。金句:"Agent = Model + Harness,我的项目大头在 Harness。"
- **Context Engineering**:分层摘要、混合检索、24k 预算、首条保留、SYSTEM_POLICY——都是在控制"模型看到什么"。
- **Multi-Agent**:Planner/Executor/Critic 是角色分工的多智能体;能讲"何时不该用多 Agent"(复杂编排有时不如单次调用基线;本项目是受控工作流,工具边界固定)是高分答案。
- **MCP**:亮点 6,跨宿主能力开放。
- **自我迭代**:只做轻量——Critic 定向重检索就是自我修正闭环;不 build 自我进化系统("不加面试没人问的花里胡哨")。
- **评测**:金标三指标 + 诚实边界(框架有、数据无)。

## 六、八股映射表(问八股就往项目锚)

| 八股问题 | 项目锚点 |
| :--- | :--- |
| 幂等怎么做的? | claim_active 主键冲突=SETNX;(内容, goalDigest) 二元组;失败路径必须释放键 |
| 重试怎么做? | Retriable/Permanent 异常类型;1/2/4s 指数退避;3 次投递;ASR 全失败必须带 cause |
| 分布式锁?(慎答) | 本项目单机,对应物是幂等认领;能讲清"为什么我不需要 Redisson"反而是加分 |
| 缓存一致性? | 先库后缓存;缓存丢失只影响速度不影响正确性;反序列化失败删缓存读库 |
| 降级/熔断? | 检索四级降级链;预算耗尽熔断进终态;观测故障不阻断主链路 |
| SSE vs WebSocket? | 单向阶段推送用 SSE(FastAPI StreamingResponse,事件名 task-status);终态主动 complete;双向才需要 WS |
| 乐观锁/并发冲突? | checkpoint 主键 upsert;uuid5 确定性 id 天然幂等;两段式修订防并发改计划 |
| 消息不丢失? | 无 MQ,等价物:终态必须落 SQLite 真源;失败必须进台账(双失败才允许向上抛) |
| 接口幂等? | 202/409/200 三态;200=结果复用;409=任务在跑 |
